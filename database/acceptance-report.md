## 3. 本次数据库修改

1. `database/schema.sql`
   - 字符集排序规则统一为 `utf8mb4_unicode_ci`，兼容 MySQL 5.7 与 8.x。
   - `submit_intent` 增加买家姓名、联系方式的去空格非空校验；MySQL 5.7 不强制执行 `CHECK`，因此不能只依赖表约束。
   - 保留并明确 `withdraw_product` 规则：仅 `ON_SALE` 可下架，`FROZEN` 拒绝下架，下架与取消待处理意向处于同一事务。
   - `publish_product` 允许 `DRAFT`、`OFF_SHELF` 发布，与前端“恢复上架”和后端 publish 接口一致。
2. `backend/src/main/resources/sql/schema-memberC.sql`
   - 同步字符集、意向非空校验，并补齐 `withdraw_product`。
3. `backend/src/main/resources/sql/schema-mysql57.sql`
   - 补齐 `DROP PROCEDURE IF EXISTS withdraw_product`，保证重复初始化时过程可重建。
4. `backend/src/main/resources/sql/procedures-mysql57.sql`
   - 同步意向非空校验并补齐 `withdraw_product`。
5. `database/acceptance.md`
   - 修正下架商品恢复上架的验收口径，避免把“前端冻结”与数据库 `FROZEN` 交易状态混为一谈。
6. `database/acceptance_test.py`
   - 新增可重复执行的独立库自动化验收脚本，包含结构、业务、并发、回滚及后端 SQL 脚本冒烟测试。

### 并发用例判定说明

DB-15、DB-19 不强制两个连接的操作先后。若意向先取得商品锁，允许“意向先提交，随后冻结/下架”；若冻结或下架先取得锁，后续意向必须失败。两种合法顺序均要求最终商品、意向、交易状态一致，并额外验证冻结或下架完成后的新意向一定被拒。

## 6. 限制与后续事项

1. MySQL 5.7 会解析但不强制执行 `CHECK`。本次已确保通过 `submit_intent` 提交时空白姓名、空白联系方式被显式拦截；若绕过存储过程直接写表，仍需应用校验、触发器或升级到 MySQL 8.0.16+ 后验证约束。
2. 本次修改的是 SQL 源文件并完成独立库验证，**未对现有业务库执行迁移或替换过程**。部署到业务环境前仍应备份，并按项目发布流程应用和复核。
3. 未执行前端页面、后端 REST 接口、密码/会话及口令码查询专项测试；这些应作为后续联调项目单独记录结果。
