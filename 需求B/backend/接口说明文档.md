# 在线购物系统（挑战需求 B）后端接口说明

《软件工程实践》第 10 组 · 第三迭代成果物
后端开发：商品、用户、订单、购物车及收藏模块

> 交付边界：本文档及本模块只涉及后端应用层（HTTP 接口、业务规则、鉴权与数据访问代码）。
> 数据库设计、建库建表、索引与数据维护由组内数据库负责人完成，不属于本模块交付内容；
> 后端按约定的表结构读写数据，不在启动时执行建表脚本。

## 1. 项目概述

本模块在基线需求（单商品线下交易）与挑战需求 A（多商品、两级类别、库存、注册登录）的基础上，
实现挑战需求 B 的后端能力：

- **订单管理**：客户下单 → 商家确认 → 备货完成 → 开始发货 → 交易完成，共 5 个状态，另含已取消。
- **订单取消**：客户可在「开始发货」前取消；商家可在「交易完成」前取消；取消后自动回补库存。
- **商品预选**：商品收藏、购物车管理、购物车多商品批量下单、购物车商品转收藏。
- **商品与类别**：多商品、两级类别、库存为 0 自动下架、浏览与搜索、多图与富文本描述。
- **客户**：自由注册（用户名/密码/电话/默认交易地点）、登录、历史订单；商家查看客户与购买历史。

### 技术栈

## 3. 通用约定

### 3.1 统一响应

所有接口返回 JSON：

```json
{ "code": 200, "message": "ok", "data": { } }
```

- `code = 200` 表示成功，`data` 为业务数据。
- 失败时 HTTP 状态码与 `code` 一致，`message` 为可直接展示的中文提示，`data` 为 `null`。

| code | 含义 | 典型场景 |
| --- | --- | --- |
| 200 | 成功 | — |
| 400 | 参数或业务校验失败 | 库存不足、超过库存、状态参数非法、类别层级非法 |
| 401 | 未登录或登录失效 | 缺少 token、密码错误、token 过期 |
| 403 | 身份不符 | 用买家 token 访问商家接口 |
| 404 | 资源不存在 | 商品/订单/客户不存在 |
| 409 | 状态冲突 | 用户名重复、订单状态已变动、不可取消、类别非空 |
| 500 | 服务端异常 | 未预期错误 |

### 3.2 认证

1. 登录/注册接口返回 `token`。
2. 后续请求携带请求头：`Authorization: Bearer <token>`。
3. token 有效期 168 小时，载荷包含角色（`SELLER` / `CUSTOMER`）与用户 ID。
4. 受保护路径：
   - `/api/admin/**`（除 `/api/admin/login`）→ 仅 `SELLER`
   - `/api/customers/me/**` → 仅 `CUSTOMER`
   - 商品浏览、搜索、类别树、客户登录/注册无需 token。

### 3.3 分页

分页接口返回：

```json
{ "records": [], "total": 12, "page": 1, "size": 20 }
```

`page` 从 1 开始；`size` 取值 1–100，超出自动收敛。

### 3.4 状态与枚举

| 枚举 | 取值 | 说明 |
| --- | --- | --- |
| 订单状态 | `PLACED` / `CONFIRMED` / `PREPARED` / `SHIPPED` / `COMPLETED` | 客户下单、商家确认、备货完成、开始发货、交易完成 |
| 取消 | `CANCELLED` | 已取消 |
| 商品状态 | `ON_SALE` / `OFF_SHELF` | 在售 / 已下架 |
| 下架原因 | `MANUAL` / `SOLD_OUT` | 手动下架 / 库存为 0 自动下架 |
| 角色 | `SELLER` / `CUSTOMER` | 商家 / 客户 |

## 5. 接口详细说明

### 5.1 认证

#### 5.1.1 卖家登录

`POST /api/admin/login`

请求：

```json
{ "username": "admin", "password": "admin123" }
```

响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "role": "SELLER",
    "username": "admin",
    "id": 1
  }
}
```

失败：401 `用户名或密码错误`。

#### 5.1.2 客户登录

`POST /api/customers/login`，请求与响应同上，`role` 为 `CUSTOMER`。

#### 5.1.3 客户注册

`POST /api/customers/register`

```json
{
  "username": "alice",
  "password": "abc123",
  "phone": "13900001111",
  "defaultTradePlace": "图书馆一楼大厅"
}
```

校验：用户名 3–20 位且唯一；密码 6–32 位；电话、默认交易地点必填。
注册成功直接返回 token（同登录响应），无需二次登录。
重复用户名：409 `用户名已被注册`。

### 5.2 商品与类别（公共）

#### 5.2.1 商品浏览/搜索

`GET /api/products?keyword=车灯&categoryId=5&page=1&size=50`

- `keyword` 可选，对商品名称与描述做模糊匹配。
- `categoryId` 可选；传一级类别时自动包含其下级类别商品。
- 仅返回 `ON_SALE` 商品；库存为 0 的商品已自动下架，不会出现。

响应 `data`：

```json
{
  "records": [
    {
      "id": 2,
      "name": "便携车灯",
      "description": "适用于夜间骑行，USB 可充电。",
      "price": 59.00,
      "stock": 12,
      "imageUrl": "https://example.com/light.png",
      "images": ["https://example.com/light.png"],
      "categoryId": 5,
      "categoryName": "骑行装备",
      "status": "ON_SALE",
      "sales": 0,
      "createdAt": "2026-11-18T18:15:41"
    }
  ],
  "total": 1,
  "page": 1,
  "size": 50
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `price` | number | 单价，两位小数 |
| `stock` | int | 剩余库存 |
| `imageUrl` | string / null | 封面图 |
| `images` | string[] | 商品全部图片，第一张为封面 |
| `status` | string | `ON_SALE` / `OFF_SHELF` |
| `sales` | int | 累计销量 |

#### 5.2.2 商品详情

`GET /api/products/{id}`，响应为单个 `ProductView`；不存在返回 404。

#### 5.2.3 类别树

`GET /api/categories`

```json
{
  "code": 200,
  "message": "ok",
  "data": [
    {
      "id": 1,
      "name": "数码电子",
      "parentId": null,
      "children": [
        { "id": 3, "name": "手机配件", "parentId": 1, "children": [] },
        { "id": 4, "name": "电脑周边", "parentId": 1, "children": [] }
      ]
    }
  ]
}
```

### 5.3 收藏

#### 5.3.1 收藏列表

`GET /api/customers/me/favorites` → `ProductView[]`（包含已下架商品，便于用户回看）。

#### 5.3.2 收藏 / 取消收藏

- `PUT /api/customers/me/favorites/{productId}`：收藏，重复调用不报错，`data` 为 `null`。
- `DELETE /api/customers/me/favorites/{productId}`：取消收藏，`data` 为 `null`。

商品不存在时返回 404。

### 5.4 购物车

#### 5.4.1 购物车列表

`GET /api/customers/me/cart/items`

```json
{
  "code": 200,
  "message": "ok",
  "data": [
    {
      "productId": 2,
      "name": "便携车灯",
      "price": 59.00,
      "stock": 12,
      "quantity": 2,
      "imageUrl": "",
      "status": "ON_SALE"
    }
  ]
}
```

#### 5.4.2 加入购物车

`POST /api/customers/me/cart/items`

```json
{ "productId": 2, "quantity": 1 }
```

- 同一商品重复加入时**数量累加**。
- 商品必须 `ON_SALE`，累加后数量不得超过库存；否则 400 `商品库存不足，请调整数量`。

#### 5.4.3 修改数量

`PUT /api/customers/me/cart/items/{productId}`

```json
{ "quantity": 3 }
```

数量为**更新后的绝对值**，需 ≥ 1 且 ≤ 库存；购物车中不存在该商品返回 404。

#### 5.4.4 移出购物车

`DELETE /api/customers/me/cart/items/{productId}`，幂等。

#### 5.4.5 购物车转收藏

`POST /api/customers/me/cart/to-favorites`

```json
{ "productIds": [2, 3] }
```

将所选商品加入收藏并从购物车移除；所选商品必须存在于当前客户购物车中。

### 5.5 订单（买家）

#### 5.5.1 下单

`POST /api/customers/me/orders`

```json
{
  "productIds": [1, 2],
  "tradePlace": "图书馆一楼大厅"
}
```

- `productIds` 为**购物车中勾选**的商品，后端按购物车数量下单，不允许直接指定数量。
- 价格以数据库当前售价为准，返回订单中的 `items` 为下单时快照。
- `tradePlace` 可选，缺省取客户注册时的默认交易地点。
- 下单成功扣减库存、清理对应购物车条目；库存扣至 0 时商品自动下架。

响应：单个 `OrderView`。

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "id": 12,
    "orderNo": "B-1",
    "customerId": 2,
    "buyerName": "buyer",
    "buyerPhone": "13800000000",
    "tradePlace": "图书馆一楼大厅",
    "status": "PLACED",
    "totalAmount": 758.00,
    "createdAt": "2026-11-18T18:15:41",
    "items": [
      { "productId": 1, "name": "城市通勤折叠车", "price": 699.00, "quantity": 1, "imageUrl": null },
      { "productId": 2, "name": "便携车灯", "price": 59.00, "quantity": 1, "imageUrl": null }
    ],
    "allowedActions": ["CANCELLED"],
    "cancelledBy": null
  }
}
```

失败场景：

| 场景 | 响应 |
| --- | --- |
| 购物车内容已变化 | 400 `购物车已变动，请刷新后重新选择商品` |
| 商品已下架 | 400 `商品名 已下架` |
| 库存不足 | 400 `商品名 库存不足` |

#### 5.5.2 历史订单

`GET /api/customers/me/orders` → `OrderView[]`，按订单 ID 倒序，包含已完成与已取消订单。

#### 5.5.3 订单详情

`GET /api/customers/me/orders/{id}`；非本人订单返回 404。

#### 5.5.4 取消订单

`POST /api/customers/me/orders/{id}/cancel`

- 仅 `PLACED`、`CONFIRMED`、`PREPARED` 可取消（开始发货前）。
- `SHIPPED` 之后返回 409 `订单已开始发货，无法取消`。
- 取消成功后库存与销量回补，因售罄自动下架的商品自动恢复上架。

### 5.6 订单（商家）

#### 5.6.1 全部订单

`GET /api/admin/orders` → `OrderView[]`（含 `buyerName`、`buyerPhone`，`allowedActions` 按商家身份计算）。

#### 5.6.2 推进订单状态

`PUT /api/admin/orders/{id}/status`

```json
{ "status": "CONFIRMED" }
```

- 只允许按状态机逐级推进，不能跳跃、不能回退。
- 目标状态与当前状态不匹配时返回 409 `订单状态已变动，请刷新后重试`。
- 交易完成或已取消的订单不可再推进。

#### 5.6.3 商家取消订单

`POST /api/admin/orders/{id}/cancel`

- `PLACED`、`CONFIRMED`、`PREPARED`、`SHIPPED` 可取消（交易完成前）。
- `COMPLETED` / `CANCELLED` 返回 409。

### 5.7 商家商品与类别管理

#### 5.7.1 商品管理列表

`GET /api/admin/products?keyword=&categoryId=&status=&page=1&size=20`

- 返回全部商品（含下架），`status` 可选 `ON_SALE` / `OFF_SHELF`。
- 其余字段与公共商品列表一致。

#### 5.7.2 发布商品

`POST /api/admin/products`

```json
{
  "name": "公路自行车",
  "description": "<p>铝合金车架，<strong>支持富文本</strong></p>",
  "price": 1299.00,
  "stock": 5,
  "imageUrl": "https://example.com/bike-1.png",
  "images": [
    "https://example.com/bike-1.png",
    "https://example.com/bike-2.png"
  ],
  "categoryId": 5
}
```

规则：

- 名称必填（≤100 字），价格 > 0，库存 ≥ 0。
- `images` 最多 9 张；`imageUrl` 缺省时取第一张图片作为封面。
- `description` 存储富文本 HTML，字段为 `TEXT`。
- 发布时库存为 0 → 商品直接为 `OFF_SHELF`（原因 `SOLD_OUT`），需补货后才会自动上架。

#### 5.7.3 编辑商品

`PUT /api/admin/products/{id}`，请求体同发布。

- 库存改为 0 → 自动下架（`SOLD_OUT`）。
- 因售罄下架的商品补货（库存 > 0）后自动恢复 `ON_SALE`。
- 手动下架的商品编辑后仍保持下架状态。

#### 5.7.4 上架/下架

`PUT /api/admin/products/{id}/status`

```json
{ "status": "OFF_SHELF" }
```

- 上架（`ON_SALE`）要求库存 > 0，否则 400 `库存为 0，无法上架，请先补充库存`。
- 手动下架原因记为 `MANUAL`。

#### 5.7.5 类别管理

- `GET /api/admin/categories`：两级类别树。
- `POST /api/admin/categories`：`{ "name": "运动户外", "parentId": null, "sortOrder": 3 }`，返回新类别 ID。
- `PUT /api/admin/categories/{id}`：请求体同上。
- `DELETE /api/admin/categories/{id}`：

| 场景 | 响应 |
| --- | --- |
| 存在子类别 | 409 `请先删除子类别` |

| 试图创建/移动到三级 | 400 `类别最多支持两级` |

## 6. 核心业务规则

### 6.1 订单状态机

```
PLACED（客户下单）
   │ 商家确认
   ▼
CONFIRMED（商家确认）
   │ 商家标记备货完成
   ▼
PREPARED（备货完成）
   │ 商家开始发货
   ▼
SHIPPED（开始发货）
   │ 商家标记交易完成
   ▼
COMPLETED（交易完成）
```

任一非终态可按规则转入 `CANCELLED`（已取消）。

### 6.2 取消规则

| 身份 | 可取消状态 | 说明 |
| --- | --- | --- |
| 客户 | `PLACED`、`CONFIRMED`、`PREPARED` | 订单处于「开始发货」前 |
| 商家 | `PLACED`、`CONFIRMED`、`PREPARED`、`SHIPPED` | 订单处于「交易完成」前 |

取消副作用：回补商品库存、回退销量；若商品此前因库存为 0 自动下架（`SOLD_OUT`），则自动恢复上架；
手动下架的商品保持下架。

### 6.3 可执行动作 `allowedActions`

前端不自行判断按钮，完全根据服务端返回的 `allowedActions` 渲染：

| 状态 | 买家 | 商家 |
| --- | --- | --- |
| `PLACED` | `CANCELLED` | `CONFIRMED`、`CANCELLED` |
| `CONFIRMED` | `CANCELLED` | `PREPARED`、`CANCELLED` |
| `PREPARED` | `CANCELLED` | `SHIPPED`、`CANCELLED` |
| `SHIPPED` | 空 | `COMPLETED`、`CANCELLED` |
| `COMPLETED` / `CANCELLED` | 空 | 空 |

### 6.4 库存与自动下架

1. 商品库存随下单实时扣减，下单在事务中完成。
2. 库存扣至 0 时自动置为 `OFF_SHELF`，原因 `SOLD_OUT`，买家列表与搜索不再返回。
3. 取消订单回补库存后，`SOLD_OUT` 商品自动上架。
4. 商家补货（编辑库存 > 0）同样会触发自动上架。
5. 商家手动下架（`MANUAL`）不受库存影响，取消订单也不会自动上架。

### 6.5 并发一致性（接口行为保证）

- 下单在单个事务内完成：校验购物车 → 校验商品状态与库存 → 扣减库存与销量 → 写订单与明细 → 清理购物车，
  任一步失败整体回滚。
- 同一商品并发下单时保证库存不会被超卖；取消订单与下单并发时库存回补与扣减不会丢失。
- 订单状态推进带当前状态校验，并发重复推进同一订单只有一个请求生效，其余返回 409。

## 7. 数据层依赖

数据库表结构、索引、建表脚本与数据初始化由数据库负责人负责，本节只说明后端接口运行所依赖的数据约定，
便于双方对接，不构成数据库设计交付物。

后端按现有表结构读写以下数据实体：

| 实体 | 后端依赖的关键信息 |
| --- | --- |
| 卖家 | 用户名唯一、密码摘要 |
| 客户 | 用户名唯一、电话、默认交易地点 |
| 类别 | 两级父子关系与排序 |
| 商品 | 单价、库存、状态、下架原因、销量、富文本描述 |
| 商品图片 | 所属商品、图片 URL、排序 |
| 收藏 | 客户与商品的唯一组合 |
| 购物车 | 客户与商品的唯一组合、数量 |
| 订单 | 订单号唯一、状态、总金额、取消方、买家与交易地点快照 |
| 订单明细 | 下单时的商品名称、单价、数量、封面快照 |

对接约定：

- 收藏与购物车需保证「同一客户 + 同一商品」记录唯一，接口的幂等语义依赖该约束。
- 金额字段需支持两位小数，后端以 `BigDecimal` 读写。
- 订单明细为下单时快照，商品后续改价/改名不影响历史订单。
- 若表结构需要调整，由数据库负责人变更并同步后端，后端不自行修改库表。
