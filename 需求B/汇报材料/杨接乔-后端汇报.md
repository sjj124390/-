## 三、各模块实现说明

### 3.1 认证与权限

- 卖家与客户分别登录，登录成功返回 JWT，载荷包含角色（`SELLER` / `CUSTOMER`）、用户 ID、用户名，有效期 168 小时。
- 密码使用 BCrypt 摘要存储，登录时校验，不保存明文。
- 客户支持自由注册：用户名 3–20 位且唯一、密码 6–32 位、电话与默认交易地点必填；注册成功直接返回 token。
- `AuthInterceptor` 统一拦截 `/api/admin/**` 与 `/api/customers/me/**`：
  - 未带 token 或 token 失效返回 401；
  - 角色不匹配返回 403；
  - 商品浏览、搜索、类别树、登录注册不拦截。
- 卖家改密需校验原密码，新密码长度 6–32 位且不能与原密码相同。
- 首次启动自动初始化卖家 `admin` 与演示买家 `buyer` 账号，便于课堂演示。

### 3.2 商品与类别

- **浏览与搜索**：支持关键词对商品名称、描述做模糊匹配；按类别筛选时，传一级类别会自动包含其下级类别商品；分页参数自动收敛到 1–100。
- **数据可见性**：公共列表只返回 `ON_SALE` 商品，商家列表可查看全部并按下架状态筛选。
- **多图与富文本**：一个商品最多 9 张图片，自动去重，未单独传封面时取第一张图片作为封面；描述支持 HTML 富文本。
- **库存与自动下架**：
  - 发布或编辑时库存为 0，商品自动置为 `OFF_SHELF`，原因记为 `SOLD_OUT`；
  - 补货后自动恢复 `ON_SALE`；
  - 手动下架记为 `MANUAL`，补货也不会自动上架；
  - 上架时校验库存必须大于 0。
- **两级类别**：
  - 只允许两级，二级类别不能再挂子类别；
  - 类别不能把自己设为父类别；
  - 删除前校验：存在子类别返回 409，类别下仍有商品返回 409。

### 3.3 收藏与购物车

- 收藏基于「客户 + 商品」唯一记录实现，重复收藏不报错，接口幂等；收藏列表包含已下架商品，方便用户回看。
- 购物车加入同一商品时数量累加，累加后不能超过库存。
- 修改数量使用绝对值覆盖，数量需 ≥ 1 且 ≤ 库存，购物车中不存在该商品返回 404。
- 购物车转收藏在事务中完成：先写收藏，再从购物车移除，避免只成功一半。

### 3.4 订单

- **下单**只允许从购物车勾选商品，后端按购物车中的数量下单，不接受前端直接指定数量。
- 下单流程在一个事务中完成：
  1. 校验勾选商品是否仍在购物车；
  2. 按主键升序 `SELECT ... FOR UPDATE` 锁定商品行；
  3. 校验商品是否在售、库存是否充足；
  4. 扣减库存、累加销量，库存为 0 自动下架；
  5. 写入订单与订单明细快照；
  6. 清理对应购物车条目。
- **订单状态机**：`PLACED → CONFIRMED → PREPARED → SHIPPED → COMPLETED`，只允许逐级推进，不能跳跃或回退。
- **取消规则**：
  - 客户只能在「开始发货」前取消（`PLACED`、`CONFIRMED`、`PREPARED`）；
  - 商家可在「交易完成」前取消（`PLACED` 到 `SHIPPED`）；
  - 取消后回补库存与销量，因售罄自动下架的商品自动恢复上架，手动下架的商品保持下架。
- **前端按钮契约**：订单响应中返回 `allowedActions`，由服务端按「当前身份 + 当前状态」计算，前端不自行判断按钮。
- **订单快照**：订单明细固化下单时的商品名称、单价、数量与封面，商品后续改价、改名不影响历史订单。

### 3.5 客户与商家管理

- 买家个人中心返回用户名、电话、默认交易地点、注册时间，以及订单数与累计消费。
- 商家客户列表返回全部注册客户及其购买统计，`totalSpent` 只统计未取消订单。
- 商家可查看指定客户的购买历史，订单响应中带买家姓名与电话，便于线下交易联系。

## 四、技术实现要点

1. **分层结构**：`controller → service → repository`，请求体与响应视图分别放在 `dto.Requests`、`dto.Views`，职责清晰。
2. **统一响应**：所有接口返回 `{ code, message, data }`；分页统一为 `{ records, total, page, size }`。
3. **全局异常处理**：业务异常、参数校验失败、JSON 格式错误、未预期异常分别映射为 400 / 401 / 403 / 404 / 409 / 500，`message` 为可直接展示的中文提示。
4. **并发控制**：
   - 下单与取消都先锁订单行，再按主键升序锁商品行，保持一致的加锁顺序，降低死锁概率；
   - 库存校验与扣减在同一事务内完成，避免超卖；
   - 推进订单状态时先锁订单行，再校验目标状态是否为当前状态的下一步，防止并发重复推进。
5. **配置外置**：数据库地址、账号、JWT 密钥均支持环境变量覆盖，便于联调与部署。
6. **跨域联调**：允许前端从本地文件或 `5500` 端口直接调用，支持 `GET/POST/PUT/DELETE/OPTIONS`。
