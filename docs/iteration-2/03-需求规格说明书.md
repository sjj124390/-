# 第二次迭代需求规格说明书

- 项目名称：在线购物系统
- 项目组：第10组
- 需求分析任务负责人：陆贻辉
- 日期：2026-10-22
- 文档版本：本轮需求初稿

## 一、概述

本轮在基线功能基础上，重点规范新增的商品手动下架、状态变化及购买意向处理规则，为前端、后端、数据库开发提供统一依据。其余基线需求仍以第一次需求规格书为准，不在本文重复展开。

## 二、用户角色

| 角色 | 功能 |
|---|---|
| 买家（无需注册） | 浏览商品、填写购买意向、保存查询口令、查看处理结果 |
| 卖家 | 登录后台、发布与管理商品、查看意向、确认线下交易结果、手动下架、查看历史、修改密码 |

## 三、本轮功能需求

### FR-01 手动下架商品

- 操作者：已登录卖家。
- 前置条件：商品当前为“在售”，且不处于待结束的交易流程。
- 操作：卖家点击“手动下架”，系统展示二次确认信息。
- 结果：确认后将商品调整为“手动下架”，前台不再允许提交购买意向；旧商品保留历史。
- 异常：商品非在售或已进入交易流程时，拒绝操作并说明原因。

### FR-02 未完成意向统一处理

- 触发条件：FR-01成功执行。
- 系统行为：将该商品所有尚未成功的购买意向终结为失败/取消等不可继续成交的状态。
- 查询结果：相关口令不再作为有效购买意向使用；查询时提示“口令码已失效”或等效文字。
- 限制：系统没有自动通知买家的功能，卖家确认窗口必须明确提示此影响。

### FR-03 商品状态与历史

- 在售：允许买家提交意向。
- 交易冻结/交易中：不允许直接手动下架。
- 已售：表示交易成功并留在历史。
- 手动下架：表示卖家主动停止出售，旧记录保留在历史。
- 手动下架后，卖家可以发布新商品，不应删除旧商品或交易记录。

### FR-04 交易处理

- 卖家按既有流程处理交易成功或失败。
- 系统应同步更新商品与购买意向状态。
- 已经成功或失败的交易不能被重复确认。
- 如商品被交易流程占用，应先结束交易，再根据状态判断是否允许下架。

### FR-05 购买口令查询

- 买家提交意向后获取查询口令。
- 正确且有效的口令可查询该意向处理进度。
- 被撤销、失效或过期的口令不得继续作为有效凭证。
- 查询结果不展示其他用户的姓名、联系方式等私人信息。

## 四、业务流程

**商品正常出售：** 卖家发布 → 商品在售 → 买家查看 → 提交意向 → 卖家处理交易。

**手动下架：** 卖家发起下架 → 判断商品状态 → 显示二次确认 → 卖家确认 → 下架商品及终结未成功意向 → 历史保留。

**异常路径：** 商品交易中/冻结中 → 拒绝直接下架 → 提示先处理交易或冻结状态。

## 五、数据与约束

| 数据对象 | 必要信息 | 约束 |
|---|---|---|
| 商品 | 编号、名称、价格、描述、图片、状态 | 价格大于0；状态变化必须符合业务规则 |
| 购买意向 | 编号、商品编号、买家姓名、联系方式、状态 | 商品不可购买时不得新增有效意向 |
| 查询口令 | 关联意向、校验摘要、有效期 | 失效/过期后不得继续作为有效凭证 |
| 交易记录 | 商品、选中意向、交易结果、处理时间 | 成交结果不能重复确认 |

## 六、非功能要求

1. 系统为课程演示项目，优先保证主要业务流程可运行、可验证。
2. 关键状态更新应保证数据一致性；并发请求不得出现两件商品同时在售或一笔交易重复成功。
3. 后台敏感操作应校验卖家身份，不得仅依赖浏览器本地登录状态。
4. 输入字段需进行基本校验；查询口令不得在普通日志中明文记录。

## 七、验收场景

| 编号 | 操作 | 预期结果 |
|---|---|---|
| AT01 | 卖家对在售商品手动下架 | 弹出二次确认；确认后状态为手动下架 |
| AT02 | 对交易中的商品直接下架 | 拒绝操作，提示先结束交易 |
| AT03 | 对手动冻结中的商品直接下架 | 按明确的冻结解除规则处理，不直接越过限制 |
| AT04 | 下架存在待处理意向的商品 | 所有未成功意向失效，无法继续成交 |
| AT05 | 用失效口令查询 | 返回“口令码已失效”或等效提示 |
| AT06 | 下架后发布新商品 | 新商品可在符合唯一在售约束下发布，旧商品留在历史 |
| AT07 | 未登录直接请求后台下架接口 | 服务端拒绝敏感操作（若未实现则列为待修复） |

以上为计划验收用例，不表示已经执行通过。
