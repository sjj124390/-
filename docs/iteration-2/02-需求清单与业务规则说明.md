# 第二次迭代需求清单与业务规则说明

- 项目名称：在线购物系统
- 项目组：第10组
- 需求分析任务负责人：陆贻辉
- 日期：2026-10-22
- 范围：沿用基线需求，整理本轮新增及需澄清的规则

## 一、系统范围

系统为单卖家、单件在售、线下交易模式。买家无需注册，浏览在售商品后提交购买意向并领取查询口令；卖家负责商品管理、查看意向、处理交易、查询历史和修改密码。不包含购物车、在线支付与多卖家业务。

## 三、关键业务规则

### 1. 商品状态

- 在售：允许浏览、提交购买意向；满足条件时可以手动下架。
- 交易冻结/交易中：不允许直接手动下架，须先结束交易。
- 已售：商品进入历史，不可继续购买。
- 手动下架：商品离开当前在售位置，进入历史；可发布新商品，旧商品记录不删除。

“手动下架”不等于“交易冻结”，不能使用同一个状态含糊处理。

### 2. 手动下架处理

1. 卖家在后台选择在售商品，点击手动下架。
2. 系统显示二次确认，并提示将使尚未成功的购买意向失效，且不会自动通知买家。
3. 卖家确认后，系统修改商品状态，并统一结束该商品未成功的购买意向。
4. 买家再查询受影响意向时，应得到“口令码已失效”等明确提示。
5. 商品保留在历史中，卖家可以发布新商品。

对于交易中、冻结中等不符合条件的商品，系统拒绝直接下架并提示原因。

### 3. 交易处理

- 交易成功：选定意向成功，商品已售，其余未处理意向不得继续成交。
- 交易失败：记录失败结果，商品能否恢复在售按对应交易规则处理。
- 商品状态与意向状态变更应一致，不能仅改变页面显示。

### 4. 口令与隐私

- 口令用于查询意向结果，不是买家直接确认成交的凭证。
- 查询不应暴露其他买家联系方式。
- 口令失效后不得继续作为有效意向使用。

## 四、需待确认的事项

1. 课程完整挑战需求是否还包含其他新功能或额外验收要求。
2. 手动冻结、交易冻结、排队中意向的正式定义和优先级。
3. 商品再次上架是否仅允许创建新商品，或允许恢复旧商品。
