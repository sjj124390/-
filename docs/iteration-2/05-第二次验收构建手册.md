# 第二次成果验收：构建与部署过程手册

项目：第10组在线购物系统；整理日期：2026-11-11。

## 1. 源码与环境

代码仓库：https://github.com/sjj124390/-

第二次迭代需求规格说明书：https://github.com/sjj124390/-/blob/main/docs/iteration-2/03-%E9%9C%80%E6%B1%82%E8%A7%84%E6%A0%BC%E8%AF%B4%E6%98%8E%E4%B9%A6.md

技术环境：JDK 8、Spring Boot 2.7.18、Maven、MySQL 8、原生 HTML/CSS/JavaScript。Docker 部署需要 Docker Compose v2。

## 2. 源码构建

从仓库根目录运行：

```sh
cd backend
mvn clean package
```

成功后生成 `target/online-shopping-backend-1.0.0.jar`（这是 Maven 内部工件版本，**不等于**本轮 Docker 镜像的 2.0.0 标签）。前端无需 npm 构建。

## 3. Docker 部署（第二次验收）

根目录 `compose.yaml` 使用第二次验收独立镜像版本 `2.0.0`，不覆盖第一次验收的 `1.0.0`。

本机从源码构建并运行：

```sh
docker compose config --quiet
docker compose build
docker compose up -d --no-build --wait --wait-timeout 240
docker compose ps
```

若已确认 GHCR 包的读取权限且三镜像已经成功发布，也可使用：

```sh
docker compose pull
docker compose up -d --no-build --wait --wait-timeout 240
```

三镜像：`ghcr.io/sjj124390/online-shopping/backend:2.0.0`、`frontend:2.0.0`、`database:2.0.0`。

浏览器：`http://127.0.0.1:5500/index.html`（买家）、`http://127.0.0.1:5500/login.html`（卖家后台）。

镜像镜像构建、发布和测试的真实状态，以 GitHub Actions 运行记录为准：https://github.com/sjj124390/-/actions/workflows/docker-images.yml。**镜像标签文字并不证明构建成功，须核对成功运行记录与可拉取性。**

## 4. 运行验证

既有 Docker 集成测试在**新建、可丢弃的空数据库**上运行：

```sh
python3 deploy/docker/smoke_test.py --allow-write
```

请勿对真实业务数据库执行，因为脚本会写入演示数据。

第二次迭代还需重点演示：在售商品下架预览、二次确认、待处理意向取消、口令失效、交易中禁止下架、历史商品保留。

前一次的 17 项容器链路检查属于首次版本的历史证明，不自动等于第二次挑战需求全部通过。第二次容器构建和验证必须查看本轮成功的 Actions 记录；新增功能验收需要另行验证。

## 5. 停止服务和常见问题

```sh
docker compose logs --tail 100 backend database frontend
docker compose down
```

`docker compose down` 不删除命名数据卷；**不要**在需保留数据时使用 `docker compose down --volumes`。

注意：GHCR 包可能需要单独设为 Public，公开仓库不等于容器镜像自动公开。离线镜像包需在相关 Actions 成功运行后的 Artifacts 下载，或另行发布 GitHub Release，不能用第一次的镜像包冒充第二次的版本。
