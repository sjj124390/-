# 需求与实现对照

第10组在线购物系统；版本 1.0.0；2026-10-20。

原始需求规格说明书：[Requirement‐Specification](https://github.com/sjj124390/-/wiki/Requirement%E2%80%90Specification)。本页用于对照原需求与交付代码，不替代老师的需求基线，也不擅自删除未完成需求。

## 1. 角色与范围

| 角色 | 用例 |
|---|---|
| 买家（免注册） | 浏览商品、填写姓名与联系方式提交购买意向、保存口令码；通过 API 查询意向状态 |
| 卖家 | 登录、发布商品、查看意向、冻结/解冻、标记交易结果、查看历史商品、修改密码 |

系统采用单卖家、单件在售、线下交易模式；不包含购物车、在线支付和多卖家。早期评审报告提及的购物车等内容与需求规格不一致，本次以需求规格说明书为对照依据。

## 2. 核心用例与实际行为

| 编号 | 需求/用例 | 前置条件与操作 | 当前代码行为 | 核对结论 |
|---|---|---|---|---|
| R01 | 展示商品 | 买家打开商品页 | 返回名称、描述、图片、价格及状态 | 已有实现，待现场复测 |
| R02 | 提交购买意向 | 在售商品；填写姓名及联系方式 | 保存意向，返回查询口令码 | 已有实现，待现场复测 |

| R05 | 后台登录鉴权/联系方式仅卖家可见 | 未登录请求后台 API | 未实现服务端 token 验证；仅页面跳转保护不足以满足该需求 | 未完成 |

## 3. 当前交易流程

买家浏览 → 提交意向并获口令码 → 卖家查看意向 → 选择意向冻结 → 卖家确认线下结果。成功：旧商品已售，其他意向关闭；失败：商品恢复在售。前端适配层“标记成功”内部依次调用冻结与结束交易。

原需求中的“买家提交即冻结”和“成交后自动生成新商品”尚未按原文字落实。需求基线变更必须由课程要求或教师澄清决定，不能仅因当前代码不同就改写为已达标。
