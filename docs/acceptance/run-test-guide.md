# 运行与测试手册

第10组在线购物系统；2026-10-20。

新增可复现的容器集成测试 `deploy/docker/smoke_test.py`：全新 Docker 测试库中验证 Nginx、前后端、数据库和核心交易流。执行与真实构建日志获取见 [Docker 手册](docker-guide.md)。下文保留原脚本的使用限制，不能把旧脚本输出当作新容器测试结果。

## 1. 前置条件

按[部署手册](deployment-guide.md)启动专用课程测试数据库、后端 8080 及前端 5500。接口自动化测试会创建商品/意向、变更交易状态并修改演示账号密码，只能在隔离的演示环境执行。

## 2. 既有自动化脚本

脚本：[backend/e2e_test.py](https://github.com/sjj124390/-/blob/main/backend/e2e_test.py)，使用 Python 标准库，无 pip 依赖。它测试原生 `/api/admin/*`、`/api/intents` 等接口，不是浏览器自动化。

执行前请检查并调整脚本：

1. `BASE` 默认为 `http://localhost:8080/api`。
2. 脚本开头有硬编码的 Windows MySQL 客户端路径和演示账号，且会删除商品、意向和交易记录。必须改为本机专用测试库配置；不能直接对真实数据运行。
3. 若已经手动准备了空测试库，可在本地副本中去掉这段 `subprocess.run(...)` 清理，保留后面的 API 测试。注意其原版本没有检查清库退出码。
4. 测试假定卖家是 `admin/admin123`；测试中改为 `newpass123` 后再改回，若中途异常需手动确认当前密码。

运行：

```sh
python backend/e2e_test.py
```

脚本包含若干 assert，但部分步骤仅打印勾号、没有完整断言；最后的“全部通过”文字不能单独视为所有功能通过证据。保留完整终端输出，逐项检查响应、数据库及页面状态。

原测试报告提到的 `api-test.ps1`、`demo-evidence/api_e2e_result.png` 在当前展开仓库及上传 ZIP 中未找到，不将这些缺失路径列为有效成果链接。

## 3. 功能用例清单

| 用例 | 操作/输入 | 预期结果 | 执行方式 |
|---|---|---|---|
| T01 | 正确/错误卖家密码登录 | 正确可登录；错误被拒绝 | 脚本 + 浏览器 |
| T02 | 创建并发布商品 | 商品 ON_SALE，前台展示完整 | 脚本 + 浏览器 |
| T03 | 已有在售商品再发布第二件 | 拒绝第二件 | 脚本 |
| T04 | 提交有效意向 | 保存记录，返回 32 位口令码 | 脚本 + 浏览器 |
| T05 | 空姓名/空联系方式 | 返回业务错误 | 手动 API + 浏览器 |
| T06 | 正确/错误口令查询 | 正确返回状态；错误统一拒绝，不返回联系方式 | 脚本 + 手动 API |
| T07 | 原生接口选中意向冻结 | 商品 FROZEN，生成待处理交易 | 脚本 |
| T08 | 冻结时提交新意向 | 拒绝 | 脚本 |
| T09 | 交易失败 | 商品恢复 ON_SALE | 脚本 |
| T10 | 冻结后交易成功 | 商品 SOLD、选中意向 COMPLETED | 脚本 + 浏览器 |
| T11 | 手动冻结及解冻 | OFF_SHELF/ON_SALE；前台按钮与状态联动 | 浏览器 |
| T12 | 修改密码、旧/新密码登录 | 旧密码失败，新密码成功；测试后恢复演示密码 | 脚本 + 浏览器 |
| T13 | 历史商品列表 | 已售商品可查询 | 浏览器 |
| T14 | 未登录直接请求后台 API | 应拒绝；当前后端缺鉴权 | 手动 API；已知缺口 |
| T15 | 买家首次提交后自动冻结 | 应立即冻结且拒绝第二次；当前实现不符合 | 浏览器/API；已知缺口 |
| T16 | 成交后自动上架同款新品 | 应生成新记录并上架；当前未实现 | 浏览器/API；已知缺口 |
